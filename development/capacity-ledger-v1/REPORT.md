The ledger uses one explicit filesystem/epoch/source-manifest/observer/policy context. Exclusive creation consumes the new file even on setup failure. A reserve validates bounded duplicate-free request/observation bytes, their exact pins, source and policy context, explicit UTC sampling/decision chronology, monotonic elapsed metadata, generation and positive full-phase amount. BEGIN IMMEDIATE serializes cooperating callers. Existing complete charges remain deducted; the unchanged 512MiB per page/phase planner refuses the full15GiB case. Reservation row, exact request and observation bytes, full charge, exact admission receipt and next generation commit together. The returned receipt is those exact committed bytes.

Reservation IDs and run/phase pairs are unique. Reusing the same ID with identical input refuses DUPLICATE_RESERVATION; changed input refuses IDENTITY_CONFLICT. A lost acknowledgement after successful commit leaves the row fully charged. Read-only reconcile returns the stored receipt only for its exact input digest and explicitly forbids launch/redispatch; ABSENT_NOT_RETRY_AUTHORITY never authorizes automatic retry. No release or state-transition API exists. All API-created rows remain RESERVED and fully charged; the planner also conservatively charges RUNNING, COMPLETED_CHARGED and AMBIGUOUS when they occur in cooperating-context fixture data. No caller may create another run/phase to bypass an uncertain prior operation.
