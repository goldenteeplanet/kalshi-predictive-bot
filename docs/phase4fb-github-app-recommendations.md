# Phase 4FB — Approval-Gated GitHub Integration Recommendations

This phase makes recommendations only. It installed or authorized no App, changed no repository setting, read no secret value, and made no runtime, database, service, or exchange mutation. The Phase 4FA App inventory remains `UNKNOWN` because the existing OAuth credential cannot enumerate GitHub App installations; that uncertainty is fail-closed.

| Integration | Minimum purpose and scope | Data/secrets and principal risks | Reversibility and recommendation |
|---|---|---|---|
| OpenAI Codex GitHub integration | Review/answer repository questions; exact availability and requested permissions must be verified in the account UI | Selected source, diffs, prompts, and metadata may leave GitHub for OpenAI; third-party processing and excessive PR/write grants are risks; cost/plan unknown | Revoke installation/access. **VERIFY BEFORE APPROVAL**; restrict repository selection and grants; never grant administration. |
| GitHub Actions | Existing CI; `contents:read`, with job-specific additions only | Workflow metadata/logs/artifacts; token, fork, injection, and dependency risks | Disable workflows/revert YAML. **KEEP AND HARDEN** using pinned actions and least privilege. |
| Dependabot | Dependency alerts and update PRs; contents/PR write only for updates | Dependency manifests and metadata; automated-change and supply-chain risk | Disable feature/remove config. **ENABLE WITH APPROVAL**; prefer before Renovate. |
| CodeQL | Static analysis; `security-events:write`, `contents:read` and only documented workflow grants | Source analyzed by GitHub; false positives, runner/action supply chain | Disable setup/revert workflow. **REPOSITORY-LOCAL CONFIG**, then require stable result. |
| Secret scanning + push protection | Detect/block committed credentials; repository settings change | Git content/signatures processed by GitHub; bypass governance and plan availability | Disable settings. **ENABLE WITH APPROVAL**, record bypass policy. |
| Artifact attestations | Bind build artifacts to workflow identity; `id-token:write`, `attestations:write`, and documented package/content access | Artifact digest/provenance; OIDC and overly broad token risk | Stop producing attestations/revert workflow. **DEFER UNTIL release artifacts need it**. |
| Rulesets + required checks | Prevent unsafe merge; repository settings write/admin approval | Check and branch metadata; lockout/bypass risk | Disable or revise ruleset. **ENABLE WITH APPROVAL** after checks stabilize. |
| Slack / Teams | Optional CI/security notifications; external-write webhook/App | Repository, actor, check, and incident metadata leaves GitHub; webhook secret and channel disclosure | Revoke webhook/App. **OPTIONAL DEFER** until notification SLO exists. |
| Sentry / Datadog / PagerDuty | Optional error, telemetry, or on-call routing | Runtime/event metadata leaves repository; DSN/API/integration secrets, privacy, alert fatigue, and plan cost | Revoke token/integration. **DEFER UNTIL NEEDED**; no production telemetry is justified by this paper-only phase. |
| Renovate | Alternative dependency automation | Similar manifest/PR access and bot token risks; hosting/cost varies | Remove App/config. **DEFER; DEPENDABOT FIRST**. |
